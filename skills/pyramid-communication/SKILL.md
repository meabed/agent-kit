# Pyramid Principle

## State the answer

Write one sentence that states the recommendation, decision, result, or required action. A reader
should know what matters and what to do from that sentence alone. If the source does not support an
answer, state the decision needed or the confirmed finding instead of manufacturing certainty.

## Add supporting points

Support the answer with two to four points at the same logical level:

- Make them mutually exclusive: no point repeats or contains another.
- Make them collectively exhaustive for the decision: cover every material reason, or state the
  deliberate boundary.
- Use either an inductive grouping of comparable evidence or a deductive chain. Do not mix the two
  within one layer.
- Place facts, examples, numbers, and quotes directly under the point they prove.

Delete content that is neither the answer, a reason, evidence, nor the necessary next action.

## Use SCQA when context is required

For a high-stakes memo, proposal, or presentation that needs context, use four compact lines:

```text
Situation: The stable fact the audience already accepts.
Complication: The change or tension requiring attention.
Question: The decision now required.
Answer: The governing recommendation.
```

Continue with the supporting pyramid. For routine email, chat, and status updates, lead directly with
the answer.

## Check the result

1. Test whether sentence one is actionable without the rest.
2. List the middle-layer points and remove overlap.
3. Check for a missing cost, risk, timing, ownership, or alternative material to the decision.
4. Attach each evidence item to exactly one support.
5. Remove greetings, throat-clearing, repeated conclusions, unsupported claims, and caveats that do
   not alter the recommendation.
6. End with the decision, owner, deadline, or next action when one exists.

Return only the polished communication unless the user requests the SCQA, MECE audit, or rationale.
